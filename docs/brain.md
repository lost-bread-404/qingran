# 清然 brain v6（2026-10-01）

需求总表见 [requirements.md](requirements.md)，检验用的一天见 [day-example.md](day-example.md)，导入导出格式见 [state-format.md](state-format.md)。

原则：上下文是大脑，人设是他是谁；其余只为让他更聪明。回复前不调用任何模型。没有「内心」、打算单和模式：清然不替 Rosie 管日程，也不在几个人格之间切换，场面和他的样子都从上下文里来。记忆是一件一件的回忆，不是一份被整篇重写的档案。

## 回复看到的（顺序）

每轮都一样的放前面（人设、「现在」、今天的对话只往后长），模型的缓存能接着用；跟着这一句变的放最后，离她的话最近。

发给模型的每一个字都在「设置 → 高级 → 指令」里，她能改：每一步的消息（标题、说明都在里面），加上「材料的写法」（停顿、照片、想起来的每一件、夜里整理看到的每一句和每件回忆、月报的每一天怎么写）。程序只把数据换进 `{…}`（`prompts/templates.ts`、`prompts/formats.ts`），不另加字；一段（空行隔开）里的 `{…}` 都是空的，这一段连标题一起不发（`prompts/doc.ts` 的 `fillParagraphs`）。

1. `你就是清然，你要跟你的恋人Rosie互动。` + `【清然的身份】` + 身份 + 人设，后面接 `清然在床上的样子：` + 亲密设定 + ｛｝心里话、别人出场时「名字：」的写法和清然只知道他在场时的事、朗读语气的用法。像一张角色卡，场面（现在是不是在亲热、她是撒娇还是真不想）由下面的对话决定
2. `清然和 Rosie 现在（{us_when}整理的）：` + 那一小段（`us_when` 是它最后一次整理的日期和时间）
3. 对话：最近「上下文最近几条」条（她连着的几条合成一条，中间空一行；同一轮里这一句之前的几段并进这一句）（清然的回复是全文；隔了 30 分钟以上插一行「停顿」）
4. `清然此刻心里想起来的事（给你做参考用的，不用念出来）：` + 想起来的几件，按发生的先后，每件按「想起来的事 / 想起来的看懂的 / 后来」写
5. `现在是…`、`Rosie 上一次说话是 …，距现在 …`、`你心里记着、Rosie 看不到的（前面是你想这句的时间，过时了的就放下）：` + 最近 16 小时的｛｝，每句按「材料的写法 → 心里记着的一句」写成「（7 小时前，00:34）……」（怎么说话都写在人设里，这里不另加指令；她 2026-10-02 改的）
6. 这一句

她发的照片（`qr_photos`，见 `photos.ts`）：带照片的话在文字前面多一句「照片」（默认「（发来 1 张照片）」），最近 3 条带照片的话把照片本身一起给模型（Grok 能看 JPG / PNG），更早的只剩那句文字。

「人设放在哪」选「第一条消息」时，这一步的第一条 system 消息原样改成她说的第一句，后面接她写的那句固定回答。空的块整块不放。模型回空（多半是拒绝）时依次重试：去掉 2、4 → 只留人设和最近 8 条，并可换到备用模型。

## 怎么想起来（`memory.ts`、`memory-search.ts`、`embed.ts`）

- 查的是：她这一句（算两遍）加前面三句。
- **按意思**（有向量时）：每件回忆存好后算一个向量（正文 + 关键词 + 线），她这句话也算一个，比谁意思最近。接口是任何 OpenAI 兼容的 `/embeddings`：环境变量 `EMBED_BASE_URL`（以 `/v1` 结尾）、`EMBED_API_KEY`、`EMBED_MODEL`；没有就用这个 Neon 分支的 AI Gateway（`NEON_AI_GATEWAY_BASE_URL` + `NEON_AI_GATEWAY_TOKEN`，模型 `qwen3-embedding-0-6b`）。意思接近度至少 0.48（2026-10-01 用故事线实测：相关的 0.52–0.74，不相关的 0.36–0.47），取最好的 4 件，离第一名不超过 0.1 的才要；她说的名字、东西在哪件里出现，那件再加一点。回复只等她这句话的向量 1.5 秒，等不到这一轮就按字面找。向量在每轮回复后、夜里整理后补算，一次 64 件。
- **按字面**（没有向量、接口没配好、出错或被拒时）：文字切成两个字一段的小片（英文按词），在正文和关键词里找；一个小片在他们最近 1500 条对话里越常见，分量越轻（「姐姐」「小猫」几乎不算，「林泽」「项圈」算得重）。BM25 达到门槛的取最贴近的 4 件，不到第一名一半的不要。
- 两种方式都再按重要度、多近、被想起过几次稍微优先；最贴近的几件再带上同一条线上紧挨在前面的那件（前因），最多加 2 件。想起过的次数记下来。
- 每轮想起了哪几件、按意思还是按字面、分数多少，都记在那一轮的记录里（设置 → 高级 → 记录、标注页），以后按真实的分数调门槛。

## 人称

两个人都是「她」，所以在没人开口说的材料里，「我 / 你 / 她」都可能指错人。规则（她 2026-09-29 定的）：
- 描述她们的材料一律用名字：人设、亲密设定、故事线、回忆、清然和 Rosie 现在、时间线、时间那一行、对话标签（「Rosie：」「清然：」）、身份标题（【清然的身份】）。夜里整理写下的也用名字。
- 「我 / 你」只出现在两个人真正说出口的话里。
- 指令本身用「你就是清然」对模型说话（每轮回复的开头）。

## 谁来演：Claude 和 Grok（2026-10-04，[claude-grok-routing.md](claude-grok-routing.md)）

平时 Claude 回她；亲热时 Claude 把戏交给 Grok，亲密的场面结束 Grok 再交回来。谁在回存在 `brain_meta.data.engineMode`（`claude` / `grok`，默认 `claude`），代码在 `voice/engine.ts`，一轮怎么走在 `routes/api/talk.ts`。回复前不多调一次模型：交不交由回复自己在最开头写的记号决定（两份指令各自最后一段写着怎么交），程序只读开头几个字（`MarkCut`），记号不显示、不朗读、不保存。

- **三份人设，指令全在人设里**（2026-10-04 晚起，取代下面「两份指令」）：「人设」页有三份：只用 Grok 时的（`systemPrompt`，全部的清然）、分流时 Claude 的（`claudePrompt`，没有床上，最后是〔接〕〔转〕）、分流时 Grok 的（`intimateNotes` 这个字段，名字是历史留下的；只有床上需要的，没有身份和秘密，最后是〔回〕）。「指令 → 每轮回复」只排材料：第一段是身份（分流时 Grok 那份不带）加选中的那份人设，后面是现在、对话、想起的往事、时间。设置 → 回复 →「Claude 分流」关掉时全部由 Grok 用第一份回，没有记号、不分段落；开着时 Claude 没回上而由 Grok 代回的那条，也用第一份。
- **两份指令，各管各的**（2026-10-04 起，已被上一条取代）：「指令 → 每轮回复（Claude）」和「每轮回复（Grok）」，各有每轮回复和主动找她两页。Claude 那份没有亲密设定那一段，多一段「清然能给 Rosie 的都在话里：现实里的事用话帮她」，最后是交接（〔接〕/〔转〕）；Grok 那份带亲密设定，最后是交回（〔回〕）。人设本身也分了：她的身体、强势占有、禁忌这些只有 Grok 演的，从人设挪进了亲密设定（`migrations/0059`，挪之前两段都存进了 `qr_profile_versions`）。
- **Claude 在回时**：用 Claude 那份指令；去掉 Grok 那几段里写的｛｝；当天对话里 Grok 演的那几段（`meta.scene = "grok"` 的她的话和他的回复）各收成一行「材料的写法 → 亲热」（默认「（两人亲热了一阵）」）。Claude 的回复写完才一起发出去、一起念（它的字是一阵一阵来的，边来边念时声音会断、字会跳）。回复以〔接〕开头：去掉记号照常显示、朗读、保存，下一轮起 Grok 回；以〔转〕开头（或者只有〔接〕没有字、或者 Claude 拒绝）：这条不显示、不保存，同一轮用 Grok 重答她这一句（她这一句标成 Grok 那段的）；Claude 一个字都没出来就出错 / 超时 / 回空：这一轮改由 Grok 回，谁在回不变，这条不算 Grok 那段、不收起。
- **Grok 在回时**：用 Grok 那份指令（带亲密设定，最后是交回）。回复以〔回〕开头：去掉记号，下一轮起 Claude 回。没写就一直是 Grok。她这时说的话和他的回复都标 `scene: "grok"`，他这时写的｛｝标成 `thread = '亲热'`（Claude 拿不到）。
- **亲热后睡着**：只在清然主动找她时（`first`）：Grok 演的那段之后她 30 分钟以上没说话，对话最后接一行「材料的写法 → 亲热后没再说话」（默认「（亲热完 Rosie 就没再说话，睡过去了或者晕过去了）」），他据此决定发什么、发不发。她自己回来说话时不插这一行，不管隔了多久都接着对话往下（她 2026-10-04 定的：她走神了一小时回来，模型却当她刚睡醒）。
- **Claude 想多久**：设置 → 回复 → 「Claude 想多久再回」（Anthropic 的 effort：快 / 中 / 慢），默认快。中档时它每轮先想 9–11 秒，对语音对话太慢。
- **换回 Claude**：只在 Grok 写〔回〕，或者分开超过「设置 → 回复 → 分开多久后清然来找你时换回 Claude」（默认 30 分钟）后清然由 Claude 写的主动消息真的存下发出去了、而且写的时候她没有说话（`reach.ts` 里调 `engine.ts endScene`）。她离开多久都不会自己换回（她 10/4 走开一小时回来想接着亲热，换回的 Claude 接不上）。Claude 看到「（两人亲热了一阵）」后她接着那段说时，写〔转〕交给 Grok。
- 换人只跟着她留下来的回复走：被撤掉的那次（她接着说了、改了）不换。每条回复的 `meta.engine` 记着是谁写的。
- **Claude 的接入**：直连 Anthropic（`src/lib/lover/claude.ts`，环境变量 `ANTHROPIC_API_KEY`），朗读照样是 xAI。消息原样换成 Anthropic 的格式：对话前面的 system 消息是系统提示，对话里和对话后面的 system 消息（停顿、想起来的事、现在几点）在原来的位置作为她那边的文字；对话要从她开始，所以对话第一条是他的时，前面补一条「……」（只有这一处是程序加的字，记忆关着时才会遇到）。缓存（prompt caching）打两个点：系统提示末尾、他上一条回复末尾（想起来的事和时间在对话后面、每轮都变，只缓存到末尾的自动缓存命中不了）。Claude 一定先想再答，不发温度；长度上限 16000（想的也算在里面）；超时 90 秒。

## 模型

Claude：设置 → 回复里选，默认 `claude-opus-5-5`（还有 `claude-sonnet-5-5`、`claude-sonnet-5`），价格在 `brain/config.ts`（缓存写入、缓存命中分开算）。Grok 和其他步骤都在设置 → 高级 → 指令里按步骤换（Grok 回复的模型在设置 → 回复里也能选）。默认：Grok 回复 grok-4.20 reasoning（主动找她也用它；回空时再试一次同一家的 reasoning 模型，不用不思考的模型），温度她自己定（默认 1.0）；夜里整理 `editor` grok-4.3 medium（超时 240 秒）；月报 `report` grok-4.3 medium。
