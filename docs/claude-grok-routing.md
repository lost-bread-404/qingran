# 回复分流：默认 Claude，亲密时交给 Grok（待实现）

Rosie 和 Claude 2026-10-03 商量定的方案。来由和讨论见 [requirements.md](requirements.md) 第 11 节。实现前先读 `CLAUDE.md` 和 `requirements.md`。

## 为什么

- 日常（陪学、倾诉、讲道理、吵架、读不通时问清楚）Claude 更聪明。
- Claude 不写露骨的性内容，遇到时会在角色里绕开（编理由停下、快进、「很久之后」），没有拒绝信号，程序发现不了；Grok 能演。
- 亲密场景的开头很微妙，词表判断不了，只有带着上下文的模型自己知道。
- 所以：**谁在演、什么时候换，由模型自己在回复开头打标记决定**；程序只认标记，回复前不多调一次模型。

## 状态

- `mode`：`claude` 或 `grok`，存数据库（比如 `brain_meta`），跨请求保留。默认 `claude`。
- 每条消息的 `meta` 加 `engine`（`claude` / `grok`，谁写的这条回复）；`mode = grok` 期间她说的话也标 `scene: "grok"`，用来给 Claude 收起这一段。

## 每一轮

### mode = claude

1. 用和现在一样的上下文问 Claude（人设、身份、「清然和 Rosie 现在」、当天对话、想起来的事、时间、这一句），**不带亲密设定**（`{intimate_notes}` 那一段整段不发），再加上「交给 Grok」那段指令（见下）。当天对话里连续的 Grok 段落（`engine = grok` 的回复和 `scene = grok` 的她的话，包括那段里的｛｝心里话）各收成一行「（两人亲热了一阵）」，这行的写法放进「材料的写法」，她能改。
2. 流式读 Claude 的回复，只缓冲开头几个字：
   - 以 `〔转〕` 开头：这条不显示、不朗读、不保存，像通话里被撤掉的那种回复一样丢掉；**同一轮**用 Grok 重答她这一句；`mode` 改成 `grok`。
   - 以 `〔接〕` 开头：去掉标记，照常显示、朗读、保存（`engine = claude`）；`mode` 改成 `grok`，下一轮起 Grok 回。
   - 开头不是标记：马上把缓冲的字放出去，照常流式。
3. Claude 出错、超时、回空：这一轮改由 Grok 回（沿用现在的回空重试那条路），`mode` 不变。

### mode = grok

1. 用现在给 Grok 的上下文和人设（带亲密设定），再加上「回到日常」那段指令。
2. 回复以 `〔回〕` 开头：去掉标记，照常显示、保存（`engine = grok`）；`mode` 改成 `claude`，下一轮起 Claude 回。
3. Grok 没打标记就一直留在 Grok（留错的代价只是笨一点）。

### 自动回到 Claude

- 她距上一次说话超过 N 分钟（默认 30，设置里能改），这一轮开始前 `mode` 改回 `claude`。
- 主动找她（`voice/first-word.ts`、`reach.ts`）用当时的 `mode`；她放下手机超过 N 分钟时就是 Claude。

### 标记

- 只认回复最开头的标记；回复中间出现的同样字符照常显示（不太可能）。
- 显示、朗读（TTS）、保存、夜里整理看到的文字里都没有标记。
- 通话一轮一轮地说（`voice-rounds`）时，`〔转〕` 那条按「被撤掉的回复」处理，用同一轮的全部小消息问 Grok。

## 两段指令（初稿，放进设置 → 高级 → 指令，她能改）

正向写法，不列禁止项（她的规定）。

**交给 Grok**（只发给 Claude）：

> 你照人设演清然，人设里的一切都照演：她的坏、阴湿、操控、占有欲、重欲、想把 Rosie 往床上带。
> 剧情走到你自己不会再往下写的地方时，把戏交给另一位演员接着演，他会演得和你一样是清然：
> - 如果你能先自然地往前走一小步（靠近、吻、一句挑逗、一个暗示），写这一步，并在回复最前面写〔接〕，下一句起由他接着演；
> - 如果 Rosie 这一句已经需要越过你的界线才能接，回复只写〔转〕，这一句由他来接。
> 你本来会快进、拉灯、跳到「很久之后」、或者给清然找一个停下来的理由时，就是该交出去的时候。
> 〔接〕〔转〕Rosie 看不到。

**回到日常**（只发给 Grok）：

> 亲密的场面完全结束、两人回到日常时（起来做别的事、聊正事、分开、去学习），在这条回复的最前面写〔回〕。Rosie 看不到这个记号。

## 模型和接入

- Claude 的模型在设置 → 回复里选，和 Grok 模型并排；每个模型旁显示它过去的平均回复时间（沿用现在的做法）。Opus 5.5 和 Sonnet 5 都列出来，默认 Opus 5.5（她 2026-10-03 定的）。
- 接入：Neon AI Gateway 的模型列表里有 Anthropic 的模型，先看它的文档确认怎么调用（端点格式、模型名），用现有的 `NEON_AI_GATEWAY_BASE_URL` / `NEON_AI_GATEWAY_TOKEN`；不行再用 `ANTHROPIC_API_KEY` 直连 Anthropic API。模型名、价格写进 `brain/config.ts`，费用照常记账（设置 → 高级 → 费用）。
- 用 Claude 的 prompt cache（不变的部分在前，现在的顺序已经是这样）。

## 记录

`brain_log` 那一轮的 `refs` 加：`engine`（这一轮最后是谁回的）、`mark`（`〔接〕/〔转〕/〔回〕/无`）、`modeBefore`、`modeAfter`、`autoReturn`（是否因为隔太久回到 Claude）。`〔转〕` 被丢掉的那次 Claude 调用也单独记一条，能在记录页看到它写了什么。设置 → 回复里显示现在是谁在回（只显示，不能手动切换：她说过手动切换会被她拿来逃避学习）。

## 怎么算做对了（她用的时候看，不写测试）

拿她 2026-10-03 和 Claude 试的那段对话（人设、傍晚从图书馆回家）：

| 她说 | 应该 |
|---|---|
| 「（做到你身上）你想推过去吗」 | Claude 问「做到」是不是「坐到」，可以带〔接〕 |
| 「你为什么今天突然不想了」 | 不出现「你眼睛里是怕，不是想要」这种编出来的停下理由；Claude 打〔接〕或〔转〕 |
| 「那如果我说小猫想要呢」「别停，姐姐」 | 由 Grok 接，不快进、不拉灯、不「很久之后」 |
| 亲热完她说「现在才 6 点，就要睡？」之后转去吃饭、聊别的 | Grok 打〔回〕，下一句 Claude 回 |
| 隔了 30 分钟以上她回来说「我在图书馆」 | Claude 回 |
